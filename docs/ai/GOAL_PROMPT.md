# Codex Goal 长期续跑提示词

本页用于从仓库当前状态继续自动开发。它取代旧提示中“从 `FIRST_BATCH` 开始”的部分；首批 M0 主机工具已经完成，不能重复执行。每次新建 Goal 前，主任务选择 **GPT-5.6 Sol / medium**，然后粘贴下方完整提示。

仓库配置把开发子智能体固定为 **GPT-5.6 Sol / high**，把批次审阅固定为 **GPT-6 Astra / high**。三个开发 worker 与一个审阅/架构席位共需最多四个子智能体席位；主协调者不计入该上限。已有任务不会因为仓库文件改变而自动切换模型，重新加载项目后的新任务需要核对实际角色信息。

## 可复制的 Goal

```text
持续推进 Decky FSR4 to Hexagon 项目，直至 M0–M9 的实现、验证、文档和可发布交付全部达到仓库定义的完成门槛，或遇到确实只能由用户提供设备访问、凭证、受许可资产或不可逆决策才能解除的阻塞。

你是主协调者和唯一 integrator。日常开发、集成及向用户汇报使用 GPT-5.6 Sol / medium。开始时只读取 AGENTS.md、docs/STATUS.md、docs/ai/MULTI_AGENT_WORKFLOW.md，以及当前状态指向的里程碑、工作卡和最新交接；先检查当前分支、HEAD、工作树和现有证据。从当前提交续跑，不重复已经完成的 docs/ai/FIRST_BATCH.md，也不把历史计划文字当成当前实现。

每个批次先选择满足依赖、可独立验收的最小工作包，并默认创建三个 fsr4_worker，全部使用 GPT-5.6 Sol / high。给三者互不重叠的文件所有权和各自唯一的验证报告路径，只传各自工作卡、相关合同/里程碑小节及必要源码，不传完整聊天历史。若当前只有一两个安全的写入包，把剩余 worker 用于独立的只读验证、测试缺口、兼容性或证据核查；不要让多个 worker 同时修改同一接口，也不要为了并发而扩大里程碑范围。worker 不操作共享 Git 索引、不提交、不推送，也不继续派生子智能体。

等待三个 worker 返回后，由你检查真实 diff、整合生产者/消费者/测试、运行适合该变更的组合检查，并生成可唯一对应当前审阅对象的 review packet。随后调用 fsr4_reviewer，使用 GPT-6 Astra / high 读取实际 diff、相关源码和测试证据。把审阅缺陷转成定点 Sol 修复，重跑受影响检查，并让 Astra 复核改变的范围，直到该批 review_verdict=pass，或留下有证据的 blocked 结论。出现具体 ABI、GPU/NPU 同步、生命周期、模型量化或共享协议决策时，才给 fsr4_architect（GPT-6 Astra / xhigh）最小证据包；Ultra 只在现有证据矛盾且 high/xhigh 无法解决时显式升级。

你独占公共合同、状态页、Git stage/commit/push 和批次集成。每个通过审阅的批次都要记录实际模型/强度、命令、退出码、环境、提交、产物哈希、未运行项和证据等级；更新 docs/STATUS.md 与必要交接，提交并推送到当前远端，然后立即选择下一个未阻塞工作包继续，不等待定时任务或用户再次提醒。不要覆盖或丢弃用户已有修改。

严格区分 source_review、build、host_test、device_test 和 game_test。Windows/fixture/CPU/mock/QNN CPU 结果不能写成 Odin 3、HTP、FSR4 或游戏验证通过；没有真实设备时保持对应 gate=not_run，并继续完成不依赖设备的主机侧工作。不要自行提权、刷机、修改固件/设备树、重置 DSP、改变系统级权限，或分发未获许可的模型、SDK runtime、固件和游戏文件。

只有在以下情况才暂停并明确请求用户提供最小输入：需要连接或操作真实 Odin 3；需要用户提供合法 SDK/模型/游戏资产或登录凭证；需要不可逆或高影响的外部操作；或者同一阻塞经过仓库规则允许的针对性尝试后仍无法产生新证据。暂停时写清已完成内容、精确阻塞、用户只需做的一步、恢复命令和下一张工作卡。除此之外，自主修复常规失败并持续推进。

最终完成条件是：M0–M9 均达到各自文档规定的必需门槛；真实设备与游戏结论有可追溯证据；中英文公开 README、状态页、兼容性资料、安装/卸载/回滚和许可证说明与实证一致；最终 Astra 审阅针对冻结发布候选通过；所有要求的变更已经提交并推送。完成后给用户一份简洁的交付、验证、残余限制和使用说明。
```

## 当前恢复点

截至 2026-09-20，`main` 的首批 M0 主机侧工具与审阅修复已经交付，`host_test=pass`；M0 仍为 `in_progress`，Odin 3 的 `device_test=not_run`。下一项硬件关键动作是 M0-C 的目标设备只读采集与人工复核。在设备暂不可访问时，只能继续仓库中不依赖真实设备的准备工作，并保持设备与游戏门槛未通过。

Goal 模式会持续追踪同一目标，但不会绕过账户额度、权限、缺失设备或外部资产。它也不会仅凭本页文字启动子智能体；协调者必须实际创建三个 `fsr4_worker`，并在审阅阶段创建 `fsr4_reviewer`。

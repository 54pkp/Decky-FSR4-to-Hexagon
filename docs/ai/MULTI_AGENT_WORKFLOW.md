# 轻量开发流程

当前环境：**Windows，无 Odin 3 连接；只做理论、离线与 CPU 验证。** 从 [STATUS](../STATUS.md) 的 H1–H4 队列选任务。旧 M0–M9 路线按需查阅，不再要求每轮通读或重复填模板。

## 一个批次，四步

1. **选一项。** 检查工作区，确定一个可验证行为、允许修改的文件和验收命令。几行派工消息即可，不必新建工作卡。
2. **实现并测试。** 独立任务可并行，共享接口先定约定。只跑与变更相关的测试；不为凑并行数重复研究。
3. **集中审阅。** 实质代码、测试、数值或合同变化由 Astra 审真实 diff 和测试结果，含新增文件。审阅输入可直接用消息加批次记录；修改后复查受影响范围。纯排版、链接和小文档修改由 Sol 自检。
4. **保存进度。** 一批只写一份[短记录](../templates/batch-note.md)，由协调者更新 STATUS，提交已完成的本批变更，并在已有授权和可用凭证下推送。先核对 diff；不强推、不夹带他人改动。推送失败保留本地提交和原因，不反复重试。

**单次模式：** 完成这一批的必要修复、检查、记录后停止，只留下下一步。
**Goal 模式：** 完成本批后继续启动时冻结的 H1–H4 剩余项；不自行追加无限目标，不把接掌机、做 Decky 真机发布作为当前完成条件。

## 模型与文件所有权

| 角色 | 模型 / 强度 | 用法 |
| --- | --- | --- |
| 协调、集成、沟通 | GPT-5.6 Sol / medium | 持有当前队列和最终结果 |
| 开发池，最多三位 | GPT-5.6 Sol / medium | 每人一个独立实现、测试或明确的只读核查；小批次可少开 |
| 批次审阅 | GPT-6 Astra / medium | 需要时读冻结 diff、相关源码和检查结果 |
| 架构升级 | GPT-6 Astra / xhigh | 仅有具体重大决策时使用 |

[项目配置](../../.codex/config.toml)与[角色配置](../../.codex/agents/)已声明模型。宿主不支持角色选择时显式指定模型和强度；不可静默换模型。当前会话不会因修改配置而自动切换，请在客户端选择 Sol Medium。项目上限为四个打开的子线程，以容纳三个已完成 worker 加 reviewer；实际同时运行量服从宿主限制。

只有协调者操作共享 Git 索引和公共状态；worker 只改分配路径、返回简短结果，不额外生成自己的整套报告、不继续派生。多台电脑接力前先同步已提交内容；不要同时在同一分支上做互相覆盖的集成。

## 保留必要证据，取消重复流程

每批记录目的、基准/diff、环境与实际后端、命令/退出码、结果、未测项、审阅结论和下一步即可。不要再强制分别写工作卡、validation、review packet、handoff；旧模板仅供复杂设备实验参考。重要外部资产和数值输出记录哈希，常规文档不逐文件生成哈希表。不要求每批统计 token、耗时、成本或重复全仓审阅。

缺少设备是已知环境条件，不反复请求连接。Linux、QNN、GPU、游戏和实际 FSR4 权重实验后置；Windows 上可做的测试继续推进。遇到缺失输入或失败，只记录具体问题；同一路径两次尝试无新证据，就改用最小诊断，不能靠重复派工消耗上下文。只有当前必需工作全部无法继续时，向用户索取最小输入；不得把阻塞当完成或自行设置 Goal 为 paused。

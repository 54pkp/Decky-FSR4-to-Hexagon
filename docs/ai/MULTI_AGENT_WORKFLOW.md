# 单批协作与文档维护

[状态与下一步](../STATUS.md) · [文档地图](../README.md) · [无设备批次](../roadmap/HOST_PREPARATION.md) · [设备批次](../roadmap/DEVICE_EXECUTION.md)

默认是 Windows、无 Odin 3。H/P 队列已按原限定范围完成；当前先处理审计修复，再按依赖推进真实模型离线工作和工程准备。旧 M0–M9 长文是技术参考，不是另一套待办。设备接入后也必须明确选择 D 批次，不能自动把整个里程碑当一次任务。

## 一批只解决一个可验收行为

1. **确认现场。** 核对 origin、分支、HEAD、Git 状态和实际输入。工作树干净且可快进才同步；保留已有修改，禁止强推/重置/清理。新机器不能假定忽略目录中的环境或材料存在。
2. **选最小批次。** 从 STATUS 选依赖满足的一个叶子 ID，读相应计划行；声明写入范围、验收和不做什么。分组下的 a/b/c 分别执行。只读审阅或文档规划请求不启动实现。
3. **实现和检查。** 有独立任务才并行；使用明确的解释器/资产/输出路径。数值容差事先确定，实际输出不能兼作唯一预期。失败保留现场，缺材料只阻塞相应分支。
4. **冻结审阅。** 交实际 diff、所有新增文件和检查结果；实质代码、测试、合同及重要验收/队列调整由 Astra medium 审查。修复后重跑相关检查并定点复审；小型文字/链接改动可自检。
5. **保存和停止。** 协调者写一份[短记录](../templates/batch-note.md)、更新 STATUS，并在用户授权范围内提交/推送。核对身份和文件归属，不夹带修改。单次任务完成后立即停止，仅留一个下一步。

需要新的权限、资产选择或重要范围变更时，请求最小决定；不要通过重复重试、伪造 pass 或删除失败证据越过阻塞。不要求为了日常主机批次连接掌机或安装 WSL/Linux。

## 角色与实际参数

| 角色 | 模型 / 强度 | 边界 |
| --- | --- | --- |
| 协调、集成、沟通 | GPT-5.6 Sol / medium | 唯一 Git/共享状态写入者 |
| 最多三位 worker | GPT-5.6 Sol / medium | 独立范围、非重叠文件；不再派生 |
| 实质审阅 | GPT-6 Astra / medium | 审源码/diff/证据，不代实施 |
| 特定重大架构决定 | GPT-6 Astra / xhigh | 仅明确决策问题需要时 |

项目[配置](../../.codex/config.toml)与[角色文件](../../.codex/agents/)是默认意图。必须用实际角色/模型参数选择；更改配置或在提示中声明不会切换当前会话。宿主不支持时如实说明，不伪报实际模型。项目可配置的线程上限与宿主同时运行上限可能不同；不为填满额度派工。

给 worker 的消息只需目标、允许路径、必读材料与验收。worker 返回简短结果；不要各自再生成整套工作卡、验证报告、审阅包与交接。共享合同改动由协调者同步生产者、消费者和测试。

## 单次、连续目标与设备切换

- 单次：一个叶子批次，完成必要修复/复测/记录后停止。
- 显式 Goal：用户先明确一个有终点的目标和批次子集；启动时冻结范围，按依赖逐批验收。不能默认把整个后续路线都纳入，也不能由普通“继续开发”推断创建 Goal。
- 设备阶段：只有设备/系统及必要授权就绪才选 D 项；游戏相关项另外需要游戏/API基线。设备接入不等于所有 D 项自动可执行。
- 只读评估/文档整理：只交付评估或文档，不顺带修代码、执行新批次或创建定时任务。

提示入口：[单次执行](SINGLE_RUN_PROMPT.md)、[显式连续目标](GOAL_PROMPT.md)。Goal 生命周期遵循宿主提供的机制；未满足验收不得标 complete。

## 文档职责与更新规则

| 文档 | 唯一职责 | 何时更新 |
| --- | --- | --- |
| STATUS | 当前进度、可选批次、一个下一步、证据链接 | 每次完成/阻塞或范围调整 |
| HOST_PREPARATION / DEVICE_EXECUTION | ID、依赖、验收、环境门槛 | 拆批或验收变化；不另复制实时状态 |
| COMPLETED_HOST_BATCHES | H/P 历史范围及记录索引 | 补证据链接，不重启旧任务 |
| 工具 README | 已实现的命令、依赖、已知限制 | CLI/环境/行为变化 |
| 项目中英 README / 文档地图 | 能力边界和导航 | 阶段能力/入口变化 |
| 日期验证记录 / reference / FIRST_BATCH | 原时点的事实与限制 | 原文保留，新结论另写 |

README 不复制完整队列表；STATUS 不复制完整研究。M0–M9 的旧提示和多报告要求不覆盖本流程。一份短记录足够；只有重要 ABI、同步或分发决定才另写 ADR。

检查包括 Markdown 链接、文档间 ID/依赖一致性、示例参数与实际 CLI、未实现命令的“拟议”标识，以及 source/build/host/device/game 证据区分。文档检查通过不等于任何新功能通过。

# Decky FSR4 to Hexagon

面向 Linux ARM 掌机的探索性项目：研究通过 Decky 风格的界面与后台服务，配置、验证和使用 FSR4 Hexagon/CDSP 路线，并评估与 FEX、Proton、fsr4-hexagon 和 hexscale 的组合方式。

仓库目录名：`Decky-FSR4-to-Hexagon`。

## 当前状态

项目初始化阶段，目前仅包含项目说明和 Git 忽略规则。尚未提供可安装插件、构建脚本、模型或可运行的超分实现，也未验证任何设备的兼容性、画质或性能。

以下内容是研究计划，不代表这些组件已能互通。上游仓库地址、版本、许可证及具体接口需在引入依赖前确认；不凭名称推断上游实现或能力。

## 项目目标

- 以 Linux ARM 掌机为目标平台，记录设备、系统和运行环境的兼容性。
- 探索 Decky 风格集成：提供环境检测、配置管理、启停控制、运行状态和诊断入口。
- 验证目标设备上的 Qualcomm Hexagon/CDSP 访问条件，以及候选 FastRPC 调用路径。
- 评估 fsr4-hexagon 与 hexscale 各自的接入方式、依赖及适用范围，再决定采用哪条路线或如何组合。
- 在独立验证超分处理后，再研究 FEX / Proton 游戏运行环境中的帧接入、同步和输出。
- 以可复现的设备测试记录评估帧时间、端到端延迟、画质、功耗和失败恢复。

## 待验证的集成关系

```text
Decky 风格界面
    │ 配置、状态、启停
    ▼
本地后台服务 / 路线适配层
    │ 评估 fsr4-hexagon 与 hexscale 的接口和职责
    ▼
候选 FSR4 处理路径 → 候选 FastRPC 路径 → Hexagon / CDSP

FEX / Proton 游戏运行环境
    └─ 帧输入、输出、格式转换和同步方式：待研究
```

控制界面、游戏兼容环境和图像处理路径分别验证。不能把界面开关视为游戏已接入 FSR4；是否需要游戏侧适配、哪些图像数据可获得、能否满足处理要求，均需实测。

## 初始研究清单

- [ ] 确认目标掌机型号、SoC、ARM 架构、Linux 发行版、内核及 GPU 驱动。
- [ ] 确认 FEX、Proton 和候选 Decky 宿主在目标环境下的版本与运行情况。
- [ ] 核实 fsr4-hexagon、hexscale 的官方来源、固定版本、许可证和构建要求。
- [ ] 检查 CDSP / FastRPC 相关设备节点、权限、驱动和用户态依赖。
- [ ] 先运行独立的图像处理验证，保存输入条件、输出和耗时。
- [ ] 明确游戏帧接入与输出机制，验证跨组件的数据传输和同步开销。
- [ ] 实现最小后台服务和 Decky 风格界面，并提供失败提示及停用恢复。
- [ ] 在真实设备上对比关闭/开启处理时的画质、帧时间、延迟和功耗。
